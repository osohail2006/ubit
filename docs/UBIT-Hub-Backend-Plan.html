1. The Thinking Process

Before writing any code or SQL, you need a mental framework. Here's how to think about a project of this scope.

Step 1: Start With "What Does the User Do?"

Don't think about tables yet. Think about actions. Open your frontend pages and ask:

💡 Thinking Exercise

For each page, write down every verb you see. For example:

  • Teachers page: browse teachers, rate a teacher, add a teacher, read reviews, reply to reviews
  • Chat page: send a message, react to a message, toggle anonymous mode
  • Requests page: post a request, filter by category, delete own request

Each bold verb hints at an API endpoint. Each noun hints at a table.

Step 2: Identify the Nouns (Entities)

From the verbs above, extract the nouns. These become your database tables:

  • "Rate a teacher" → teachers table
  • "Write a review" → reviews table
  • "Send a message" → messages table
  • "Post a request" → requests table
  • "Upload a note" → notes table
  • "Create an event" → events table
  • "Rate a location" → locations + location_reviews tables

You already have users (profiles table via Supabase Auth) — that's the central entity everything connects to.

Step 3: Ask "What Belongs to Whom?" (Relationships)

For each entity, ask: "Does this belong to a user?" and "Does this belong to another entity?"

  • A review belongs to a user and a teacher → foreign keys: user_id, teacher_id
  • A message belongs to a user (nullable for anonymous) → foreign key: user_id
  • A request belongs to a user → foreign key: user_id

Step 4: Ask "What Attributes Does Each Entity Need?"

Look at your frontend forms and data. Every input field = a column. Every displayed piece of text = a column. For example, the teacher card shows:

  • Name, department, initials, avatar color, overall score → teachers columns
  • Teaching, grading, lab grading, friendliness scores → stored in reviews, averaged at query time
  • Tags (e.g., "TOUGH GRADER") → stored as an array in reviews

Step 5: Start With the Core, Build Outward

Don't build all 7 modules simultaneously. Identify which module is the foundation:

🔑 Key Insight

Authentication + User Profiles are the foundation. Everything else (reviews, requests, messages, notes) depends on knowing who is doing the action. Build auth first, then teachers (your priority feature), then the rest.

Data Flow Example: Submitting a Teacher Review

💡 How a Request Flows Through the System

1. Student fills out the review form on /teachers/[id]

2. Frontend calls POST /api/teachers/[id]/reviews with the 4 scores + tags + remarks

3. Route handler validates input (Zod), checks JWT, verifies one-review-per-teacher limit

4. Route handler queries Supabase: supabase.from('reviews').insert({...})

5. PostgreSQL Row Level Security checks: is the user authenticated? Does user_id match?

6. If approved → row inserted, Supabase Realtime broadcasts the change, response returns success

7. Frontend updates the review list in real-time (no page reload needed)

5. Database Design — Complete Schema

The Thinking: How I Got to 11 Tables

💡 Reasoning Process

1. User is already handled — Supabase Auth creates a profiles table for you automatically. That's table #1.

2. Teachers are standalone entities — they don't belong to a user. That's table #2.

3. Reviews connect users to teachers — this is a many-to-many with extra data (scores, tags). Table #3.

4. Review replies — teachers reply to reviews. Table #4.

5. Chat is a single feed — just one messages table, no rooms needed. Table #5.

6. Requests are user posts — one table. Table #6.

7. Notes are file uploads — one table. Table #7.

8. Events are announcements — admin-only creation. Table #8.

9. Event RSVPs — tracks who's interested. Table #9.

10. Map locations — from GeoRate. Table #10.

11. Location reviews — from GeoRate. Table #11.

That's 11 tables. Each one maps to a clear user action or entity. No chat_rooms table (single feed) and no gpa_snapshots table (GPA is client-side only).

Complete SQL Schema

1. profiles

CREATE TABLE profiles (
  id         UUID PRIMARY KEY REFERENCES auth.users(id) ON DELETE CASCADE,
  first_name TEXT NOT NULL,
  last_name  TEXT NOT NULL,
  department TEXT NOT NULL,
  batch_year INT,
  avatar_url TEXT,
  role       TEXT DEFAULT 'student' CHECK (role IN ('student', 'admin')),
  created_at TIMESTAMPTZ DEFAULT now()
);

2. teachers

CREATE TABLE teachers (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name        TEXT NOT NULL,
  department  TEXT NOT NULL,
  initials    TEXT GENERATED ALWAYS AS (
    upper(
      left(split_part(name, ' ', 1), 1) ||
      left(split_part(name, ' ', 2), 1)
    )
  ) STORED,
  avatar_bg   TEXT DEFAULT '#eab308',
  created_at  TIMESTAMPTZ DEFAULT now()
);

CREATE INDEX idx_teachers_department ON teachers(department);

3. reviews

CREATE TABLE reviews (
  id                 UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id            UUID NOT NULL REFERENCES profiles(id) ON DELETE CASCADE,
  teacher_id         UUID NOT NULL REFERENCES teachers(id) ON DELETE CASCADE,
  teaching_score     NUMERIC(3,1) NOT NULL CHECK (teaching_score BETWEEN 1 AND 10),
  grading_score      NUMERIC(3,1) NOT NULL CHECK (grading_score BETWEEN 1 AND 10),
  lab_grading_score  NUMERIC(3,1) CHECK (lab_grading_score BETWEEN 1 AND 10),
  friendliness_score NUMERIC(3,1) NOT NULL CHECK (friendliness_score BETWEEN 1 AND 10),
  tags               TEXT[] DEFAULT '{}',
  remarks            TEXT,
  is_anonymous       BOOLEAN DEFAULT false,
  helpful_count      INT DEFAULT 0,
  created_at         TIMESTAMPTZ DEFAULT now(),
  UNIQUE(user_id, teacher_id)
);

CREATE INDEX idx_reviews_teacher ON reviews(teacher_id);
CREATE INDEX idx_reviews_user ON reviews(user_id);

4. review_replies

CREATE TABLE review_replies (
  id         UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  review_id  UUID NOT NULL REFERENCES reviews(id) ON DELETE CASCADE,
  author_id  UUID NOT NULL REFERENCES profiles(id),
  content    TEXT NOT NULL,
  created_at TIMESTAMPTZ DEFAULT now()
);

5. messages

CREATE TABLE messages (
  id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id      UUID REFERENCES profiles(id),
  content      TEXT NOT NULL,
  is_anonymous BOOLEAN DEFAULT false,
  reactions    JSONB DEFAULT '[]',
  created_at   TIMESTAMPTZ DEFAULT now()
);

CREATE INDEX idx_messages_created ON messages(created_at DESC);

6. requests

CREATE TABLE requests (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id     UUID NOT NULL REFERENCES profiles(id) ON DELETE CASCADE,
  title       TEXT NOT NULL,
  category    TEXT NOT NULL CHECK (category IN (
    'notes', 'carpool', 'project', 'tutoring', 'lost_found'
  )),
  urgency     TEXT NOT NULL DEFAULT 'low' CHECK (urgency IN (
    'low', 'medium', 'high', 'urgent'
  )),
  description TEXT NOT NULL,
  is_active   BOOLEAN DEFAULT true,
  created_at  TIMESTAMPTZ DEFAULT now()
);

CREATE INDEX idx_requests_category ON requests(category);
CREATE INDEX idx_requests_active ON requests(is_active, created_at DESC);

7. notes

CREATE TABLE notes (
  id             UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id        UUID NOT NULL REFERENCES profiles(id),
  title          TEXT NOT NULL,
  course         TEXT NOT NULL,
  year           TEXT NOT NULL,
  type           TEXT NOT NULL CHECK (type IN ('notes', 'past_paper')),
  file_url       TEXT NOT NULL,
  file_size      INT,
  is_approved    BOOLEAN DEFAULT false,
  download_count INT DEFAULT 0,
  created_at     TIMESTAMPTZ DEFAULT now()
);

CREATE INDEX idx_notes_course ON notes(course, year);
CREATE INDEX idx_notes_approved ON notes(is_approved, created_at DESC);

8. events

CREATE TABLE events (
  id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  organizer_id UUID NOT NULL REFERENCES profiles(id),
  title        TEXT NOT NULL,
  description  TEXT,
  event_date   DATE NOT NULL,
  event_time   TIME,
  location     TEXT,
  image_url    TEXT,
  is_published BOOLEAN DEFAULT true,
  created_at   TIMESTAMPTZ DEFAULT now()
);

CREATE INDEX idx_events_date ON events(event_date DESC);

9. event_rsvps

CREATE TABLE event_rsvps (
  id         UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  event_id   UUID NOT NULL REFERENCES events(id) ON DELETE CASCADE,
  user_id    UUID NOT NULL REFERENCES profiles(id),
  status     TEXT DEFAULT 'interested' CHECK (status IN ('interested', 'going')),
  created_at TIMESTAMPTZ DEFAULT now(),
  UNIQUE(event_id, user_id)
);

10. locations

CREATE TABLE locations (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name        TEXT NOT NULL,
  description TEXT,
  category    TEXT NOT NULL CHECK (category IN (
    'canteen', 'academic', 'resource', 'admin', 'facility', 'exit'
  )),
  lat         NUMERIC(10,7) NOT NULL,
  lng         NUMERIC(10,7) NOT NULL,
  icon_url    TEXT,
  created_by  UUID REFERENCES profiles(id),
  created_at  TIMESTAMPTZ DEFAULT now()
);

11. location_reviews

CREATE TABLE location_reviews (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  location_id UUID NOT NULL REFERENCES locations(id) ON DELETE CASCADE,
  user_id     UUID NOT NULL REFERENCES profiles(id),
  rating      NUMERIC(3,1) NOT NULL CHECK (rating BETWEEN 1 AND 5),
  comment     TEXT,
  created_at  TIMESTAMPTZ DEFAULT now(),
  UNIQUE(location_id, user_id)
);

CREATE INDEX idx_location_reviews ON location_reviews(location_id);

Row Level Security (RLS) Policies

⚠️ Important

Supabase Row Level Security ensures users can only do what they're allowed to. Without RLS, any authenticated user could read/write any row.

-- PROFILES: Public read, own write
ALTER TABLE profiles ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Public profiles" ON profiles FOR SELECT USING (true);
CREATE POLICY "Update own profile" ON profiles FOR UPDATE USING (auth.uid() = id);
CREATE POLICY "Insert own profile" ON profiles FOR INSERT WITH CHECK (auth.uid() = id);

-- REVIEWS: Public read, auth create, owner delete
ALTER TABLE reviews ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Reviews public" ON reviews FOR SELECT USING (true);
CREATE POLICY "Auth create reviews" ON reviews FOR INSERT WITH CHECK (auth.uid() = user_id);
CREATE POLICY "Owner delete reviews" ON reviews FOR DELETE USING (auth.uid() = user_id);

-- MESSAGES: Public read, auth send
ALTER TABLE messages ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Messages public" ON messages FOR SELECT USING (true);
CREATE POLICY "Auth send messages" ON messages FOR INSERT
  WITH CHECK (auth.uid() = user_id OR is_anonymous = true);

-- REQUESTS: Public read, owner manage
ALTER TABLE requests ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Requests public" ON requests FOR SELECT USING (true);
CREATE POLICY "Auth create requests" ON requests FOR INSERT WITH CHECK (auth.uid() = user_id);
CREATE POLICY "Owner delete requests" ON requests FOR DELETE USING (auth.uid() = user_id);

-- NOTES: Approved public, owner manage
ALTER TABLE notes ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Approved notes public" ON notes FOR SELECT USING (is_approved = true OR auth.uid() = user_id);
CREATE POLICY "Auth upload notes" ON notes FOR INSERT WITH CHECK (auth.uid() = user_id);

-- EVENTS: Public read, ADMIN ONLY create/update/delete
ALTER TABLE events ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Published events public" ON events FOR SELECT USING (is_published = true);
CREATE POLICY "Admin create events" ON events FOR INSERT
  WITH CHECK (EXISTS (SELECT 1 FROM profiles WHERE id = auth.uid() AND role = 'admin'));
CREATE POLICY "Admin update events" ON events FOR UPDATE
  USING (EXISTS (SELECT 1 FROM profiles WHERE id = auth.uid() AND role = 'admin'));
CREATE POLICY "Admin delete events" ON events FOR DELETE
  USING (EXISTS (SELECT 1 FROM profiles WHERE id = auth.uid() AND role = 'admin'));

-- EVENT_RSVPs: Public read, auth RSVP
ALTER TABLE event_rsvps ENABLE ROW LEVEL SECURITY;
CREATE POLICY "RSVPs public" ON event_rsvps FOR SELECT USING (true);
CREATE POLICY "Auth RSVP" ON event_rsvps FOR INSERT WITH CHECK (auth.uid() = user_id);

-- LOCATIONS & LOCATION_REVIEWS: Public read, auth write
ALTER TABLE locations ENABLE ROW LEVEL SECURITY;
ALTER TABLE location_reviews ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Locations public" ON locations FOR SELECT USING (true);
CREATE POLICY "Auth add locations" ON locations FOR INSERT WITH CHECK (auth.uid() = created_by);
CREATE POLICY "Location reviews public" ON location_reviews FOR SELECT USING (true);
CREATE POLICY "Auth review locations" ON location_reviews FOR INSERT WITH CHECK (auth.uid() = user_id);

7. Authentication Strategy

Supabase Auth Flow

💡 How Auth Works

1. Student fills signup form → Frontend calls POST /api/auth/signup

2. Your route handler validates input, checks email domain, calls supabase.auth.signUp()

3. Supabase creates the auth user, you create a row in profiles

4. JWT returned → stored in localStorage on the client

5. Every subsequent API call includes Authorization: Bearer <jwt>

6. Your middleware or route handler verifies the JWT, extracts user ID

7. Supabase RLS policies enforce what the user can read/write in the database

Key Auth Files

FilePurpose
src/lib/supabase.tsSupabase client (browser — for frontend components)
src/lib/supabase-server.tsSupabase client (server — for route handlers, uses service role key)
src/lib/auth.tsHelper to extract current user from request headers
src/middleware.tsProtects /api/* routes, attaches user context

Example Route Handler (Hand-Built)

// src/app/api/auth/signup/route.ts

import { NextRequest, NextResponse } from 'next/server';
import { supabaseServer } from '@/lib/supabase-server';
import { z } from 'zod';

const signupSchema = z.object({
  firstName: z.string().min(1),
  lastName:  z.string().min(1),
  email:     z.string().email(),
  password:  z.string().min(6),
  department: z.string(),
});

export async function POST(req: NextRequest) {
  const body = await req.json();
  const parsed = signupSchema.safeParse(body);

  if (!parsed.success) {
    return NextResponse.json({ error: parsed.error }, { status: 400 });
  }

  const { firstName, lastName, email, password, department } = parsed.data;

  // University email restriction
  const allowedDomains = ['uok.edu.pk', 'ubit.edu.pk'];
  if (!allowedDomains.some(d => email.endsWith(d))) {
    return NextResponse.json({ error: 'Only university emails' }, { status: 403 });
  }

  // Create auth user
  const { data: authData, error: authError } = await supabaseServer.auth.signUp({
    email,
    password,
  });

  if (authError) {
    return NextResponse.json({ error: authError.message }, { status: 400 });
  }

  // Create profile row
  const { error: profileError } = await supabaseServer
    .from('profiles')
    .insert({
      id: authData.user!.id,
      first_name: firstName,
      last_name: lastName,
      department,
    });

  if (profileError) {
    return NextResponse.json({ error: profileError.message }, { status: 500 });
  }

  return NextResponse.json({
    message: 'Signup successful',
    user: { id: authData.user!.id, firstName, lastName, email, department },
  });
}

8. Real-time Strategy

Chat: Supabase Realtime (Postgres Changes)

No Socket.io needed. Supabase supports real-time subscriptions directly. Since it's a single feed (no rooms), the subscription is simple:

// In your chat page component
import { createClient } from '@supabase/supabase-js';

const supabase = createClient(SUPABASE_URL, SUPABASE_ANON_KEY);

// Subscribe to ALL new messages (single global feed)
const channel = supabase
  .channel('global-chat')
  .on(
    'postgres_changes',
    {
      event: 'INSERT',
      schema: 'public',
      table: 'messages',
    },
    (payload) => {
      setMessages(prev => [...prev, payload.new]);
    }
  )
  .subscribe();

Typing Indicator

// Send typing indicator
channel.send({
  type: 'broadcast',
  event: 'typing',
  payload: { user_id: userId },
});

// Listen for typing
channel.on('broadcast', { event: 'typing' }, (payload) => {
  showTypingIndicator(payload.payload.user_id);
});
